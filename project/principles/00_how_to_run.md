# 00 · 어떻게 실험하는가 (how to run)

무엇을, 어떤 순서로, 어떤 기준으로. **이 파일과 `01`~`06` 만 읽으면 이어서
할 수 있어야 합니다.**

---

## A. 한 명령

```
cd project
./scripts/build_all.sh
```

6 단계를 고정 순서로 돌리고, **한 단계라도 실패하면 그 아래를 안 만듭니다.**

| # | 단계 | 스크립트 | 하는 일 |
|---|---|---|---|
| 1 | 게이트 (사전) | `gate_sweep.py --offline` | 검증 6 개. 실패하면 여기서 중단 |
| 2 | 순위 | `analyze_buildable.py` | 두 랭킹을 **화면에 출력**. 문서가 되기 전에 사람이 봄 |
| 3 | 사양서 | `make_samples.py` | `SAMPLES.md` 생성 |
| 4 | 렌더 + 스냅샷 | `report_buildable.py` (Blender) | 3D 이미지 11 장 + `report/<날짜>/data.json` |
| 5 | 리포트 | `build_report_2rank.py` | `report/<날짜>/report.html` |
| 6 | 게이트 (사후) | `gate_sweep.py --offline` | `data.json` 이 있어야 되는 검사(6번) |

`--offline` 을 주면 4 단계(렌더)를 건너뜁니다. 문서만 고칠 때 씁니다.

**순서가 왜 고정인가:** 이걸 기억에 맡겼다가 틀렸습니다. `report_buildable.py`
가 `form_roughness.py` 보다 먼저 돌아서, 리포트에 가장 중요한 그림이 조용히
빠진 채 발행됐습니다. **아무것도 실패하지 않았고 페이지에 빈 칸만 생겼습니다.**

## B. 게이트 — 통과해야 하는 6 가지

`scripts/gate_sweep.py`. **실패하면 종료 코드 1.** 여섯 중 넷은 실제 사고에서
역산해 만들었습니다.

| # | 검사 | 무엇을 막나 |
|---|---|---|
| 1 | 대조군이 아는 답을 내는가 | 코팅 평판이 논문 곡선을 12 % 이내로 재현, 0.05 대조판이 0.05000 |
| 2 | 기준값이 측정에서 왔는가 | **6.12 % 상수** — 아무도 안 잰 분모가 모든 배수를 5.4 배 틀리게 함 |
| 3 | 비교군이 피처·공정 **둘 다** 맞는가 | **8 배 팁 불일치**. 하나만 맞추면 공정이 다른 족이 손해 |
| 4 | 측정 기하 = 문서 기하 | **쐐기 0.1→0.9 mm** 를 사양서엔 "0.1 mm 판재"로 적음 |
| 5 | 모든 비율이 기준을 밝히는가 | "4.5 배"가 무엇 대비인지 없는 문장 |
| 6 | 후보 전원이 순위를 갖는가 | **날 배열이 순위에서 누락.** 카드는 나오는데 순위 자리만 대시 |

렌더가 필요한 1 번은 `--offline` 에서 건너뜁니다. 새 스윕 전에는 **렌더 포함**
으로 돌리십시오.

## C. 채점 기준

바꾸지 마십시오. 바꾸면 이전 결과와 비교가 끊깁니다.

**어둡기 (darkness)**
```
ρ_dh 를 입사각 0 / ±20 / ±40° 에서 잰다
→ 그중 최악값
→ 코팅 가정 3 종 (확산비 0.0 / 0.76 / 1.0) 중 최악값
→ 기하 배치 시드 여러 개의 평균 ± SEM
```
시드가 핵심입니다. 시드 1 개일 때 상위 13 개가 1.09 배 안에 몰렸는데,
**실현 산포가 3.5 % 라 그 순서는 대부분 우연**이었습니다.

**형태 (form destruction)**
```
2 mm 줄무늬를 한 pitch 에 걸쳐 16 위상으로 걸어가며 평균
→ 되돌아온 선의 rms 폭 ÷ 같은 프레임의 평판 대조군
θ = ±40°
```
16 위상이 조건입니다. 3 위상으로는 못 씁니다 — `metrics/04` 에 위상에 따라
peak 가 214 배 흔들린다고 적혀 있습니다.

**기준선 (baselines)** — 반드시 같은 문장에 명시
- 같은 코팅의 **평판**: 1.1413 % (구조가 산 것을 재는 기준)
- **맨 검정벽** 0.05 확산판: 매 프레임에 들어 있음

**빛이 어디로 가나 (where the light goes)** — 새 축, `metrics/08`
```
입사각 θ_in 에 태양, 관측각 θ_out 에 카메라
→ 같은 프레임의 램버시안 대조판으로 나눠 BRDF (1/sr) 를 읽는다
→ θ_in −80…+80, θ_out −85…+85, 5° 간격
→ 태양의 각지름 = θ_in 간격. 빈 폭을 태양이 정한다
```
읽는 법은 직선 세 개입니다. `θ_out = +θ_in` 이 역반사(프로젝터 쪽),
`θ_out = −θ_in` 이 평면거울 방향, `θ_out = 0` 이 관객입니다.

**이 축은 상호성 트릭을 쓰지 않습니다.** `metrics/01` 은 반구 전체를 적분해서
방향을 지웁니다 — 이 지표가 재는 축이 바로 그 지워진 축이라서, 같은 방법을
쓸 수 없습니다. 대신 빔과 카메라를 씁니다.

**절대값은 아직 인용 불가.** 코팅 피팅은 평판의 ρ_dh 만 구속하고 BRDF 모양은
전혀 구속하지 않습니다 (`metrics/01` 에 그렇게 적혀 있습니다). 이 지표는
바로 그 모양을 읽습니다. 지도의 **구조** — 능선이 어디 있나, 역반사선에
빛이 있나 — 는 기하학 결과라 유효하지만, 셀의 절대값은 실물 쿠폰을
고니오미터로 재기 전까지 인용하지 마십시오.

**폐기된 지표:** `metrics/03` core_frac. 분모가 측정 대상과 같이 줄어듭니다.
되살리지 마십시오.

## E. 새 실험을 추가할 때

1. **게이트를 렌더 포함으로 돌린다.** `Blender ... --python scripts/gate_sweep.py`
2. **질문 에이전트를 먼저 부른다** (원칙 05). 사후가 아니라 사전
3. 스윕 스크립트를 쓴다. 반드시:
   - `params_json` 을 행마다 기록
   - 이어달리기 가능하게 (기존 출력 읽고 끝난 것 건너뛰기)
   - 채점을 **C 절과 동일하게** — 다르게 채점하면 비교가 아니라 다른 실험
4. **기하를 렌더해서 눈으로 본다** (원칙 04). `shot3d.py`
5. 돌린다. **폴링하지 말고** GPU 없는 일로 넘어간다 (원칙 06)
6. `build_all.sh`

### 오래 도는 스윕
```
./scripts/run_queue.sh &     # 잡 순환. 잡이 죽어도 큐는 안 멈춤
./scripts/keepalive.sh &     # 큐가 죽으면 재시작, 45 분 정체 기록
touch logs/STOP              # 둘 다 정지
tail -f logs/queue.log
```

**큐가 도는 중에 `run_queue.sh` 를 고치지 마십시오.** zsh 가 루프 본문을 첫
반복 전에 통째로 파싱합니다 — 고쳐도 반영 안 되고, 이것 때문에 잡 두 개가
"넣었다"고 보고된 채 한 번도 실행되지 않았습니다. 유휴 상태에서 고치고
재시작하십시오.

**Blender 는 파이썬이 예외로 죽어도 종료 코드 0 을 줍니다.**
`--python-exit-code 77` 을 반드시 붙이십시오. 안 붙였다가 40 분짜리 잡이 1 초
만에 죽었는데 성공으로 기록됐습니다. `[확인: blender --help]`
