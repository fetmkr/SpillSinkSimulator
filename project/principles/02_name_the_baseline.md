# 02 · 모든 숫자는 기준을 밝히고, 모든 기준은 측정에서 온다

## 규칙

- **비율을 쓰면 무엇에 대한 비율인지 같은 문장에 적습니다.** 다음 줄도, 표
  제목도 아닙니다. 같은 문장입니다
- **분모는 측정값이어야 합니다.** 손으로 타이핑한 상수는 안 됩니다
- 절대량을 먼저, 비율을 나중에 씁니다

## 무엇을 잃었나

`FLAT_COATING_WORST = 0.061218` 이라는 상수 하나가 리포트·요약·사양서의 모든
"28 배 / 30 배 / 29 배"의 분모였습니다. **그 값이 나온 렌더가 저장소에
없습니다.** 아무도 재지 않았습니다.

제대로 재니 **1.1413 %** 였습니다. 5.4 배 틀렸고, 따라서 "구조가 28 배"는
실제로 **5.3 배**입니다.

더 나쁜 것: **5.3 배는 이 프로젝트가 이미 2026-08-12 에 스스로 낸 값**입니다
(`SUMMARY.md`, "0.00998 대비 5.5×"). 분모를 0.00998 에서 0.061218 로 바꾼
시점에 측정이 없었습니다. 근거 없이 만들어진 숫자가 그 뒤 모든 문서로
퍼졌습니다.

덤으로: 선행연구(Kaster 2025)와의 "3.7 배 격차" 도 이 오류의 산물이었습니다.
논문과 우리를 비교하는 주장 전체가 잘못된 분모 위에 있었습니다.

## 왜 상수가 위험한가

상수는 **출처가 없어도 문법적으로 아무 문제가 없습니다.** 렌더는 config 가
남고 CSV 행이 남지만, `X = 0.061218` 은 그냥 참인 것처럼 보입니다. 그리고 한
번 문서에 들어가면 인용이 인용을 낳습니다.

## 강제

`gate_sweep.py` 검사 2: 분모로 쓰이는 상수에 "어떻게 측정했는가" 주석이
없으면 실패. 값이 물리적으로 불가능한 범위면 실패.
